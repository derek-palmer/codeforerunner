# codeforerunner

> Your codebase gets a Forerunner; your docs finally see the light.

codeforerunner is a Python-built, model-agnostic AI documentation agent that you unleash on your repos.

Codeforerunner works against single-stack or polyglot repositories and can document each stack area plus how they interact. It:

- Scans your codebase structure, stack boundaries, integrations, and public APIs
- Generates a main README, stack-specific docs, API docs, Mermaid diagrams, and flow documentation
- Hooks into your workflow to keep docs in sync with code
- Blocks changes until documentation is updated and approved
- Lets you use the model stack you already prefer

## Features

- AI-driven repo scan
  - Understands project structure, entrypoints, key modules, integrations, stack boundaries, and likely data flows.
- Polyglot by design
  - Built in Python, but designed to document repos containing frontend, backend, worker, scripting, and infrastructure stacks together.
- Autogenerated README
  - High-level overview, setup, usage, and architecture sections.
- Stack-specific documentation
  - Generates docs that fit the detected framework or ecosystem, such as React app docs, Python service docs, Ruby worker docs, or Terraform infrastructure docs.
- API documentation
  - Extracts public interfaces, parameters, and examples.
- Mermaid diagrams
  - Renders architecture, dependency, and flow diagrams as Markdown-embedded Mermaid.
- Integration and data-flow docs
  - Explains how data enters, moves through, and exits the system across languages, services, and infrastructure.
- Doc enforcement hook
  - Optional pre-commit and CI checks for outdated docs.
- Model agnostic by design
  - Works with your preferred model provider, local runtime, or agent host.
- Approvals and guardrails
  - Requires the committer to review and accept doc changes before code lands.

## Installation

### Install from PyPI

After the first tagged release is published to PyPI:

```bash
pip install codeforerunner
```

### From source

```bash
git clone https://github.com/derek-palmer/codeforerunner.git
cd codeforerunner
uv sync --dev
uv run forerunner --help
```

### Run with Docker

```bash
docker build -t codeforerunner .
docker run --rm -it -v "$PWD:/workspace" -w /workspace codeforerunner --help
docker run --rm -it -v "$PWD:/workspace" -w /workspace codeforerunner init
```

### Run with Docker Compose

The compose setup mounts the current repository into `/workspace`, so the CLI runs against your checked-out repo instead of the image filesystem.

```bash
docker compose run --rm --user "$(id -u):$(id -g)" forerunner --help
docker compose run --rm --user "$(id -u):$(id -g)" forerunner init
```

Alternatively, use the Makefile targets which handle UID/GID automatically:

```bash
make docker-help
make docker-init
```

### Make targets for container workflows

```bash
make docker-build
make docker-help
make docker-init
make docker-run ARGS="check"
make compose-config
```

`make docker-up` is also available, but because `codeforerunner` is a CLI-first container, it is mostly useful as a quick smoke test for the default `forerunner --help` command.

## Quick start

1. Install codeforerunner.
2. From the root of your repo, run:

```bash
forerunner init
```

3. Review the generated artifacts:
- `README.md`
- `docs/apps/`, `docs/services/`, or `docs/infrastructure/`
- `docs/api/`
- `docs/diagrams/`
- `docs/flows/`

4. Accept or edit the docs, then commit as usual.

## Enforcing up-to-date docs

### Pre-commit hook

1. Install pre-commit in your target repo:

```bash
pip install pre-commit
pre-commit install
```

2. Add codeforerunner to `.pre-commit-config.yaml`:

```yaml
repos:
  - repo: https://github.com/derek-palmer/codeforerunner
    rev: v0.1.0
    hooks:
      - id: codeforerunner-doc-check
```

3. On each commit, the hook will:
- Detect code changes.
- Regenerate any affected docs and diagrams.
- Show you a diff to review.
- Fail the commit if docs are missing, stale, or not acknowledged.

### CI check

```bash
forerunner check
```

Fail the build if:

- Generated docs are out of date.
- Diagrams or flow docs are missing or inconsistent.
- The repo was changed without re-running codeforerunner.

## Configuration

Add a `forerunner.config.yaml` file at the repo root.

```yaml
include:
  - src/
  - app/
exclude:
  - tests/
  - node_modules/

adapters:
  provider: local

docs:
  readme: README.md
  api_dir: docs/api
  diagrams_dir: docs/diagrams
  flows_dir: docs/flows

enforcement:
  strict: true
```

## Maintainer release flow

Before the first public release, create the `codeforerunner` project on PyPI and configure a Trusted Publisher for:

- Owner: `derek-palmer`
- Repository: `codeforerunner`
- Workflow: `.github/workflows/publish.yml`

To publish a release:

1. Bump `version` in `pyproject.toml`.
2. Merge the release commit to the main branch.
3. Create and push a tag such as `v0.1.0`.
4. Let GitHub Actions build, verify, and publish the distributions to PyPI.
5. Verify `pip install codeforerunner` and `forerunner --help` from a clean virtual environment.
